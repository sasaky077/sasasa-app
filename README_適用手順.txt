ZERAPHIA build1918 — iPhone PWA バトルBGM消失対策

【適用】
このZIPをWebアプリの公開ルートに展開し、同名ファイルを上書きしてください。
ZIP内に含まれる index.html / version.json / js/ 以下4ファイルのみを変更します。
CSS、SW、manifest、画像、音声、Supabaseのデータは変更しません。

【対象】
index.html: 新モジュール読み込み・キャッシュ更新
version.json: build 1918
js/shooting_event.js: 戦闘コアのモジュール読込バージョン更新
js/shooting_core.js: 現在の戦闘曲を診断モジュールへ公開、OFF→ONで手動復旧、ポーズ解除時に保留復旧
js/bgm_guard.js: バトル曲のエラー復旧を新モジュールに一本化（既存ホーム/タイトル曲は変更なし）
js/bgm_battle_recovery.js: 再生位置停止の検知、タッチ起点で最大2回復旧、ログ50件

【主な仕様】
・1.2秒ごとに戦闘BGMの再生位置のみを確認（戦闘ゲームロジックには干渉しない）
・3.5秒以上再生位置が変化しない場合に異常候補として記録
・復旧処理は次のユーザー操作時のみ。1バトル2回まで、最低6秒間隔
・プレイヤーがBGMをOFF→ONにした場合は意図的な読み直しを実行
・ポーズメニューでOFF→ONした場合はメニューの「再開」を押した時に実行
・ユーザーがBGMをOFFにしたままなら自動再生しない
・再読み込みで曲の再生位置を保持するよう試行（ブラウザ次第で差異あり）

【診断】
ブラウザのコンソールで getShootingBgmDiagnostics() により最大50件の状態ログを閲覧できます。
無音が起きた直後は markShootingBgmSilent() でその時点の状態を記録できます。
ログはメモリだけに存在し、Supabase等には送信しません。

【検証・限界】
JS全4ファイルの構文検証は通過。iPhone 14実機での再現テストは未実施。
iOS自体が「再生位置は進むが実際には無音」の場合は自動検出できません。
その場合、ポーズメニューでOFF→ON→再開することで、明示的な再読み込みを試します。

【ご注意】
既存のHTML/JS/CSSを同じリリースとしてアップロードしてください。
PWAの削除・再追加はアカウントのローカル情報が失われる可能性があるため推奨しません。
